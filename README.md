# FbaBuddy

Electron 桌面办公壳。`pnpm dev` 只会打开桌面窗口，不会自动打开浏览器。

供应商、全站默认模型、搜索密钥和运行配置由后台管理。客户端只读消费内置模型，也可直接配置自己的模型；压缩、RAG、Qdrant、协议和重试等运行配置不进入客户端偏好。内置助手、技能、MCP、知识、短语由后台写入（`user_id = 0`），客户端 GET `/xxx/all` 可读不可改。自己的助手、技能、短语、通道、对话定时走 JWT `/me` 或用户通道/定时接口，不能带后台权限码。通道是把飞书等 IM 接到自己的 AI，不绑助手；定时挂在已有对话上。运行时使用 `agent_mode: chat | work | coding`。对话、项目、产物和会话工作区通过后端持久化，客户端维护界面选择状态；记忆只读可删。专家模板可一键填入助手，本轮 MCP / 技能 / 知识仍可自选。输入 `/` 弹出斜杠指令，`/polish` 润色草稿不落历史。历史气泡展示本轮模型、模式和 MCP 组合。聊天、工作、编码是三种会话模式，首条消息确定模式，后续消息、跟进和复刻沿用该模式；需要切换模式时新建对话。切走对话不会停当前生成，回来后继续看实时输出。沙箱、防护栏和原生工具由后端按模型能力自动启用。

新对话的左侧入口明确提供 FbaBuddy Chat、Work、Coding 三种模式；Chat 和 Work 也可通过新对话内容区顶部的「聊天 / 工作」切换，有消息后隐藏该切换并锁定侧栏模式入口。聊天使用紧凑输入框，搜索、MCP、快捷指令和对话设置集中在「＋」菜单，润色保留在输入框右侧；聊天不绑定项目，项目只在工作与编码模式里选择。工作使用多行输入框，新对话下方显示项目、工具入口和工作位置，添加文件留在「＋」菜单里，有消息后隐藏下方栏并将工具收进「＋」菜单。Work 与 Coding 的新对话都显示工作位置选择，默认为「在本地」，可在首条消息前选择云端；首条消息成功创建会话后固定位置，已有会话在「＋」菜单内只读显示当前位置。Coding 另外提供分支和 Worktree 控件。聊天用于问答、讨论和轻量起草，保留搜索、资料读取和已选 MCP；工作增加规划、子代理、工具编排和产物写入。FbaBuddy Coding 提供分支、Worktree、Diff、编码权限与本机/沙箱执行。发送前切换模式保留草稿，重新打开会话和左右栏分别恢复各自固定的模式。配套后端的会话 `agent_mode` 字段持久保存该选择，并校验后续请求。

## 开发

会话历史和附件统一由配套的 `ai_buddy` 后端保存，AI 推理与工具调度也由后端负责。客户端不再提供独立本地会话或存储模式选择

从固定栏「更多（⋯）> 知识库」进入，可固定到侧边栏。动态侧边栏显示知识库列表，右侧显示当前库的文件列表，支持分别搜索知识库与库内文件。可新建、编辑和删除自己的知识库，新建后选中新库；上传时从 `GET /knowledges/me` 选择目标库，也可在当前库标题旁直接上传，上传完成后展示目标库文件。内置知识库只读，删除自有知识库会连同库下文档一起删除。编辑名称和描述保留已有向量模型绑定，向量化与 OCR 运行配置由后台维护

- 历史缓存：桌面使用应用数据目录 `cache/history.sqlite` 保存服务端历史 GET 快照，按后端地址和账号隔离。网络不可用时只能查看已缓存历史，不创建或修改会话，也不恢复生成和审批操作
- 历史更新：联网成功读取后刷新缓存；生成结束自动读取服务端最终记录，即使已切走会话也会更新缓存。服务端修改会话时使相关缓存失效，删除会话时清理该会话及列表、搜索缓存
- 运行环境：在「设置 > 运行环境」配置编码执行位置和 Python、Node.js 工具运行时。桌面编码工具执行后端调度的任务，写入和命令操作逐次确认

ACP 从侧栏「更多」进入，配置本机已安装的 Agent 可执行文件和启动参数。未绑定对话的工作目录为 `~/.fbabuddy/acp`，启动时自动创建；已绑定对话使用其固定工作目录。桌面主进程启动 Agent，继承本机环境及登录状态；不自动安装 Agent。Claude Code / Codex 等需要先安装相应 ACP 适配器。配置仅保存在此设备，后端只接收所选 Agent 和一次性连接 ID。检测在本机启动程序，通过桌面 WebSocket / Redis 转发完成 ACP 握手与会话初始化，结束后关闭进程。需要桌面端与配套的 `ai_buddy` 后端；连接成功不代表推理额度已验证

编码对话复用 AG-UI 实时流，显示 ACP 工具进度和审批。等待审批期间执行过程保持展开，显示等待审批的轨迹和已等待时长。实时审批通过 `/conversations/{id}/approvals/{request_id}` 提交单次允许或拒绝，继续同一运行；切回对话可恢复未决审批。停止和归档会取消后端生成及审批等待。外部 ACP 进程运行在用户本机，ACP 轮不创建 OpenSandbox；普通内置编码助手默认通过独立连接使用桌面本机的操作系统沙箱，也可切换服务端 OpenSandbox。切换对话只取消消息流订阅，本地 Agent 继续运行；停止、归档、退出桌面或 ACP 连接断开会关闭本地进程树。反向代理需要支持 WebSocket Upgrade

客户端直接使用 `@ag-ui/core` 的原生 AG-UI 类型。`src/api` 负责构造原生 `RunAgentInput`，`src/api/stream.ts` 负责 SSE 读流，`src/features/chat` 将原生事件与快照投影为界面消息；客户端不保留独立协议层。请求顶层使用 `threadId`、`runId`、`forwardedProps`，工具中断通过原生 `resume` 回传后端的 `interruptId`，批准和拒绝均以 `resolved` 携带 `payload.approved`，续跑发送空消息列表；工作模式结束读取 `RUN_FINISHED.outcome`。原生事件及快照消息的声明字段使用 camelCase；产品扩展通过 `CUSTOM` 的 `{ name, value }` 传递，`value` 内的 `message_id`、`request_id`、`call_id` 以及 `turnContext` 内部字典按后端定义保留 snake_case。生命周期历史必须保存完整事件封装，不再从裸 `kind` 字段推断事件名称。图片生成结束后读取会话快照中的 `pydantic_ai_file` 文件活动

运行中的跟进消息通过 `/conversations/{id}/follow-ups` 保存到后端队列，切换会话或关闭客户端不会清除队列。后端负责按顺序派发，客户端读取状态并可移出待执行项；需要配套后端的跟进队列迁移。不支持实时引导的运行时会明确降级为排队，本地编码和 ACP 的自动跟进仍需要可用的桌面执行连接，派发失败会显示原因。

助手提问时，结构化输入卡片直接渲染在正文里发问的那条消息上，运行停在提问这一步等待回答，回答后卡片消失，继续后续执行。回答前不会跳过提问继续执行。对话按轮虚拟渲染，阅读位置、展开状态和代码换行偏好会在本机保留。历史首次读取最近 50 条持久消息，可分页加载并搜索完整历史。当前回合的重新生成由后端原地替换回复，历史编辑和重生成会创建关联分支，原消息保留；引用的原文位置和批注通过后端持久化。上述历史、计划、结构化问答、生命周期事件和 MCP 应用能力需要同步更新配套 `ai_buddy` 插件。

Markdown 表格支持完整 Markdown/CSV 复制与遮罩展开，文件预览支持 20 MB 以内文本、CSV 全行筛选排序分页、媒体错误重试。MCP 应用只有在服务器声明 `ui://` 资源后才加载，使用独立沙箱和宿主消息桥；写工具、发送聊天消息及下载文件均由用户在宿主界面确认。

平台启用 OAuth 的 HTTPS 内置 MCP 可在详情或聊天 MCP 选择器中连接账号。客户端通过登录 JWT 读取状态、生成授权链接和断开连接；服务商配置由管理员在后台维护。授权时桌面使用系统浏览器，Web 使用新窗口，回到应用或点击「已完成授权」查询服务端连接状态。未连接时先授权再加入本轮，发送前再次确认所选 MCP 连接；调用失败后可检查连接，已连接账号也可主动重新授权。授权链接过期或 MCP 配置变化后重新生成，客户端不接收授权码或保存服务商令牌

本机文件链接可以预览并定位行号、打开默认应用或在文件管理器中显示；Shell 代码块可在对话绑定的工作区运行和引用输出。本机编码执行、Shell 和 ACP 在运行前后捕获目录文件变化，每轮结束后提供真实差异与受保护的撤销；文件已有后续修改时拒绝覆盖。快照跳过 Git 元数据、依赖和构建目录，并受文件大小及总量限制；不完整的变更卡不显示整组撤销。OpenSandbox 暂无完整工作区回滚快照。密钥面板已具备独立提交与清除机制，由受信服务端处理器发起和消费，不作为模型可任意读取的工具暴露。

后端默认 `http://127.0.0.1:8000`。先启动 fba，再：

```bash
pnpm install
pnpm dev
```

终端里出现的 `http://127.0.0.1:5173` 只是桌面窗口加载的内部地址，不要用浏览器打开。

开发时界面变更通过 Vite 热更新；`electron` 和 `src/shared` 源码变更会自动重新编译并重启桌面窗口，编译失败时保留当前客户端。

只有调试 UI 才用网页：

```bash
pnpm dev:web
```

对话渲染预览使用真实 `Thread`、消息转换、富文本及独立内容组件，共用应用字体、主题和样式。运行后通过 Vite 打开根目录入口，支持场景切换、流式回放、审批、输入请求、附件和窄屏检查：

```bash
pnpm dev:renderings
```

入口为 `/conversation-renderings.html`，也包含在网页构建产物中。示例消息、API 响应和执行结果只在预览页内存中提供，不调用真实模型或执行命令；HTML 需要通过 Vite 开发服务或构建预览服务加载

后端地址写在项目根目录 `.env`，不要在页面里改：

```env
VITE_GLOB_API_URL=http://127.0.0.1:8000
```

可先复制 `.env.example`。开发时 `/api` 也会代理到这个地址。

项目功能需要先执行后端迁移：

```bash
fba alembic upgrade head
```

## 编码执行

新建项目可通过「源文件夹 > 添加」关联本机已有文件夹，已有项目可在「项目目录」中更换或移除目录。每个项目支持一个主目录，关联按后端、账号和项目保存在此设备。项目的新编码对话和 ACP 使用该目录；已有对话及 Worktree 保持原绑定。

项目右键支持置顶、取消置顶、在文件夹中打开、复制路径和删除项目目录。「删除项目目录」仅解除此设备上的目录关联，保留本地文件、项目和会话。置顶状态保存在项目排序中，取消置顶会恢复原排序。

Coding 的右侧边栏 Diff 面板区分已暂存和未暂存文件，并查看逐文件差异；可拖动边界调整宽度，打开时仍可继续聊天。支持手动暂存、撤销暂存和提交，提交只使用暂存区，不自动暂存或推送；撤销暂存保留文件修改。提交与提交前检查保留在 Diff 面板，每轮运行结束后的文件变更支持查看差异和撤销。新建对话的 Worktree 通过输入框上方右侧的复选开关使用，已有对话的工作位置保持固定，管理入口在「设置 > Worktree」。

右上角「右侧边栏」按钮展开或收起统一面板，新建对话默认收起。侧栏的可关闭标签、添加面板「＋」、最大化和收起按钮整合在应用顶部导航栏，与侧栏宽度对齐；侧栏内部只显示面板内容。Work 提供「侧栏对话」，Coding 另提供「Diff」，支持拖动标签排序和调整侧栏宽度；切换标签或收起侧栏保留对话草稿与运行状态。已关联本地项目的编码草稿可以在首条消息前开启 Diff，待创建 Worktree 的草稿需要先完成创建。面板布局按对话和账号保存，切换到 Work 隐藏工程标签，回到 Coding 恢复选择。

Worktree 的环境选择、基准分支、首次发送时创建、会话移交和集中管理参考 Synara。新草稿选择「新建 Worktree」后，只记录基准分支，首次发送消息时才创建独立目录和临时分支；从当前根分支创建时复制未提交变更与未跟踪文件，额外忽略文件由 `.worktreeinclude` 选择。已有对话通过「移交到新 Worktree」或「移交到本机」继续同一个会话，运行期间不能移交；不会自动提交或推送。移交回本机后保留关联 Worktree，清理通过设置显式执行。

原「文件同步」入口已移除，当前实现仅是本机文件与云端 S3 文件清单之间的显式上传下载，不会重建执行环境或迁移对话及 Git 状态。用途需重新确认后再决定产品入口，底层传输接口继续保留。

参考源码、竞品能力边界和文件传递结论见 [Worktree 与文件传递调研](docs/workspace-research.md)。

客户端仅提供 Electron 桌面应用，执行配置使用主进程接口，不提供 Web 客户端执行分支。「设置 > 运行环境 > 编码执行」配置保存在本机。默认后端为 `local`，默认目录为 `~/.fbabuddy`，可选择系统文档目录中的 `FbaBuddy` 或自定义绝对路径。新对话默认在本地工作，并使用配置的目录；首条消息前可选择云端。修改默认设置不会改变已有对话，首条消息成功创建会话后不能更改工作位置。会话执行配置和文件回退快照按后端地址及账号隔离。未绑定对话的 ACP 默认使用 `~/.fbabuddy/acp`。

- `local`：macOS 使用 Seatbelt (`sandbox-exec`)，Linux 使用 bubblewrap；系统保护不可用时拒绝执行，Windows 当前需要选择 `sandbox`
- `sandbox`：由服务端连接所选沙箱服务商，支持 `opensandbox`、`docker`、`e2b`、`modal`、`daytona`、`sprites`、`smol`、`boxlite`。远程 `/workspace` 是临时工作区，同一对话可在沙箱存活期间复用文件，销毁后未显式保存的文件会丢失；目前没有完整工作区备份或重建恢复，也不自动同步到桌面目录。通过产物功能保存的内容和聊天附件独立保存在后端；密钥仍由服务端保存

本机执行使用独立的 `/execution/bridges` WebSocket，连接与用户、对话和权限绑定。工作区外的用户私密文件不默认开放，Shell 环境不继承客户端密钥；只有 `full` 权限允许对外网络，仍保留文件系统隔离。本机执行不可用时需要用户显式选择 `sandbox`，不退回未隔离的 Shell。

「设置 > 运行环境」提供编码执行和运行组件。运行组件显示 Python、Node.js 工具运行时的状态及安装操作；AI 推理和调度由后端负责。「设置 > Worktree」独立管理当前账号在本机保留的 Git 工作区。「常规」保留应用偏好。

「设置 > 外观」的半透明窗口默认不透明度为 90%、模糊为 64，并开启「仅侧边栏」。该模式下，动态侧边栏与内容区域组成一整块实心面板，外围固定侧边栏、顶部导航栏及面板外留白共用一层半透明底色；关闭「仅侧边栏」后整窗半透明。半透明材质仅在 macOS 生效，其他平台使用实心窗口。

编码运行时仅提供应用内置的固定版本 Python 和 Node.js，不提供来源选择，也不使用系统已安装版本。默认不下载，首次使用前需在「设置 > 运行环境 > 运行组件」点击安装并确认下载；未安装时提示用户手动安装，不在聊天过程中静默下载安装。运行时保存在应用数据目录的 `runtimes`，安装包当前不包含离线运行时，支持 macOS/Linux 的 arm64 和 x64。设置中不提供 Shell 运行时条目。

桌面本地端口不会作为服务端可直接访问的 URL；当前服务端尚未提供桌面 HTTP 隧道。需要服务端访问运行中的应用时使用 `sandbox` 沙箱服务商。

## 三端构建与安装

不需要 Apple 开发者账号、Windows 代码签名证书或 Apple 公证。构建使用 ad-hoc 临时签名或未签名发布，任何人都可以下载安装，但操作系统会按未认证开发者应用处理。

### 安装包

| 平台 | 产物 | 安装方式 |
| --- | --- | --- |
| macOS Apple Silicon | `FbaBuddy-*-mac-arm64.dmg` | 打开 DMG，将 FbaBuddy 拖入「应用程序」 |
| macOS Intel | `FbaBuddy-*-mac-x64.dmg` | 打开 DMG，将 FbaBuddy 拖入「应用程序」 |
| Windows x64 | `FbaBuddy-*-win-x64.exe` | 运行 NSIS 安装器，默认按当前用户安装，无需管理员权限 |
| Linux x64 | `FbaBuddy-*-linux-x64.AppImage` | `chmod +x FbaBuddy-*.AppImage` 后直接运行 |
| Linux x64 | `FbaBuddy-*-linux-x64.deb` | `sudo apt install ./FbaBuddy-*.deb` |

macOS 使用 ad-hoc 签名，保证 Apple Silicon 可以加载应用，但没有 Apple 公证。第一次打开时在「应用程序」中按住 Control 点击 FbaBuddy，选择「打开」，再确认「打开」。如果仍被拦截，到「系统设置 > 隐私与安全性」点击「仍要打开」。只对从本仓库 Release 下载的文件执行该操作。

Windows 安装器未购买代码签名证书，SmartScreen 会显示「Windows 已保护你的电脑」。点击「更多信息 > 仍要运行」即可安装。安装器创建桌面和开始菜单快捷方式，并提供自定义安装目录。

Linux AppImage 无需安装；如果系统缺少 FUSE，先执行 `sudo apt install libfuse2`。DEB 安装会注册系统应用菜单，可使用系统包管理器卸载。

### 本机打包

`pnpm dist` 构建当前平台安装包，产物写入 `release/`：

```bash
pnpm dist
```

macOS 同时生成 x64 和 arm64：


### GitHub Actions

- `.github/workflows/ci.yml` 执行类型检查、Lint、Vitest、完整构建和 desktop 启动冒烟测试
- `.github/workflows/desktop-build.yml` 在 main、Pull Request 和手动触发时构建三端安装包，并上传 Actions Artifacts
- 推送 `v*` 标签时，同一工作流使用仓库自动提供的 `GITHUB_TOKEN` 创建 GitHub Release 并上传全部安装包及更新清单

发布前先把 `package.json` 的 `version` 更新为与标签一致，例如版本 `0.2.0` 对应标签 `v0.2.0`：

```bash
git tag v0.2.0
git push origin v0.2.0
```

GitHub Release 会同时提供自动更新所需的 `latest-mac.yml`、`latest.yml` 和 `latest-linux.yml`。未签名构建在部分 macOS 环境中可能被系统拒绝自动更新，此时重新下载最新 DMG 覆盖安装即可，用户数据不会删除。

```bash
pnpm test
pnpm test:smoke
pnpm build
```

`pnpm test` 运行 Vitest 单元测试，`pnpm build` 验证完整构建。`pnpm test:smoke` 只验证 desktop 产品能够启动并挂载渲染根节点，不覆盖业务流程，仓库不维护 e2e 测试套件。

深链格式为 Hash 路由，例如 `#/chat/<id>`、`#/settings/general`、`#/settings/channels`、`#/settings/crons`、`#/workspace/skill`。桌面端 access token 使用系统安全存储加密（`safeStorage`）；安全存储不可用时仅保留在主进程内存，重启后需要重新登录，不写入明文凭证。网页调试仍走 `localStorage`。
